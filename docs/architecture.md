# 架构说明

## 目标边界

宿主 Agent 负责理解用户意图、补齐必要参数和选择工具；Chaoxing Agent 负责确定性地选择学习通对象、发出 HTTP 请求、执行风险确认并验证结果。正式运行时不启动或控制浏览器，也不依赖学习通客户端。

浏览器只属于开发期观测手段：用于确认网页真实入口、请求字段、权限条件和成功信号。只有在 `requests` 会话中能够独立复现并验证的行为，才进入已实现动作目录。

## 组件

| 组件 | 职责 | 实现 |
| --- | --- | --- |
| 动作目录 | 动作名、领域、风险、状态、别名和实测标记 | `capabilities.py` |
| 中文路由 | 把常见中文命令转成动作与参数；不确定时返回缺失字段 | `router.py` |
| 统一运行时 | 检查动作状态、执行确认门、分发 HTTP 实现 | `runtime.py` |
| HTTP API | 登录、对象解析、请求、规范化、回读与恢复 | `api.py` |
| 确认门 | 将一次性令牌绑定到动作和规范化参数 | `approval.py` |
| MCP | 为 Agent 暴露类型化语义工具 | `mcp_server.py` |
| CLI | 诊断、脚本调用和可重复验收；复用统一运行时 | `cli.py` |

## 认证

`session.login` 调用学习通 HTTP 登录接口。用户名和密码只存在于单次调用内；密码不会写入响应、本地状态或 Cookie 文件。登录返回成功后，运行时再次请求个人空间，只有发现已认证标记才原子保存 Cookie。

Windows CLI 的 `--windows-dialog` 使用系统 `CredUIPromptForWindowsCredentialsW` 收集一次性账号和密码，并使用 `CredUnPackAuthenticationBufferW` 解包。调用不启用保存复选框；解包后的原生字符缓冲区和 Windows 返回的认证 BLOB 在使用后清零，BLOB 随后由 `CoTaskMemFree` 释放。该对话框只是 CLI 的本机输入通道，不改变 HTTP-only 运行模型，也不引入浏览器、WebDriver 或学习通客户端依赖。MCP 与无人值守调用不会自行弹出对话框。

对于学银在线等超星跨应用页面，调用方可提供可选 `target_url`。登录页的 `refer`、`/fanyalogin` 返回的跳转地址和目标页均在同一临时 HTTP 会话内完成。个人空间认证与目标页认证独立验证：前者必须出现已登录标记，后者必须到达原目标主机且未落回登录页。响应仅返回目标主机、路径、状态码和标题，不返回查询参数、`stuenc` 或 SSO 票据；任一验证失败时也不会覆盖现有 Cookie 文件。

学生课程模块还可使用 `learning_course` 与 `learning_module` 进行语义选择。运行时通过当前保存会话读取学生课程入口，在内存中构造签名目标，然后立即交给同一次登录动作；公开结果只保留课程、班级、模块及脱敏后的目标验证信息。原始模块地址不写入本地状态，也不返回给调用方。课程语义选择与原始 `target_url` 互斥。

`learning.course.homework.read` 先从当前学生作业列表解析指定作业及仅在内存中使用的签名入口，再逐跳检查预览或详情页重定向。若下一跳是 `/dowork` 答题表单，该只读动作会在请求表单前停止并回读状态；其余结果保留题目、图片、附件和当前答案，但剔除 `enc` 等会话参数。读取后只有状态与 `answer_id` 均未变化才报告成功。该动作不调用保存、重做或提交接口。

`learning.course.homework.answer.enter` 是独立的 `write` 动作，只有调用方明确选择它时才允许跟随 `/dowork`。成功结果必须到达该路径、检测到答题表单并核对 `work_id`；结果只返回表单、控件和题目结构，不返回隐藏值或签名参数，也不会自动保存或提交。进入表单可能创建或恢复答题实例，因此不能由只读详情动作隐式触发。

`learning.course.homework.redo` 使用详情页实际公开的 `/mooc-ans/work/phone/redo` 和 `workAnswerId` 参数。它会覆盖上一份作答记录，因此按 `delete` 风险执行一次性确认；只有服务器确认重做且随后进入同一 `work_id` 的答题表单才报告成功。服务器确认后若表单回读失败，动作会明确报错而不会声称完成。

作业详情页公开的 `/mooc-ans/mooc2/work/answer-list` 用于读取历次作答索引；历史记录通过页面提供的 `selectTimes` 参数读取。两类动作都只在内存中使用 `enc`，公开结果不返回历史页签名地址，并在完成后复核作业状态与 `answer_id`。当前账号已实测空记录列表；指定历史作答读取有页面协议与自动测试，但因当前账号没有非空记录，未标记真实条目验证。

后续动作从 `CHAOXING_COOKIE_FILE` 创建独立 `requests.Session`。Cookie 文件应位于仓库外；`.gitignore` 还排除了常见 Cookie 文件名和本地运行目录。

如果平台要求二次验证，登录动作返回明确错误与平台验证地址。项目不尝试绕过二次验证。

## 对象选择

课程、班级、作业、试卷、题目、成员、资源等对象统一遵循以下解析顺序：

1. 稳定平台 ID；
2. 当前结果中的序号；
3. 完整名称；
4. 唯一部分匹配。

部分匹配出现多个候选时，动作停止并返回候选清单，不自行选择。

## 风险模型

| 风险 | 示例 | 是否确认 |
| --- | --- | --- |
| `read` | 列表、详情、统计、下载 | 否 |
| `navigate` | 读取功能入口 | 否 |
| `draft` | 创建或修改未发布草稿 | 依动作目录配置 |
| `write` | 可回读验证的普通写入 | 依动作目录配置 |
| `publish` | 发布、发送、共享、提交 | 是 |
| `permission` | 教师、成员、可见性与访问权限 | 是 |
| `delete` | 删除、永久删除、清空 | 是 |
| `purchase` | 付费或消耗免费额度 | 是 |

确认令牌包含随机值，并绑定动作名与参数 SHA-256 指纹。默认五分钟过期，只能消费一次。配置 Cookie 文件后，确认记录默认保存在本机 `%LOCALAPPDATA%\chaoxing-agent`，使 MCP 的两次调用可以跨进程完成；该目录不属于仓库。

## 验证与恢复

动作只在满足可观察后置条件时返回成功。常见模式包括：

- 创建前后集合差分，并回读新增 ID；
- 修改后重新读取字段并逐项比对；
- 删除后确认对象不再出现在刷新结果；
- 发布前后检查平台状态；
- 多步修改中某一步失败时，按旧值尝试恢复。

平台只返回“已受理”而暂时不能形成最终结果时，动作返回当前任务 ID 和可继续轮询的语义动作，不把受理等同于完成。

## 机密与输出

以下内容不进入结构化结果：

- Cookie 值、密码和登录加密中间值；
- 页面临时令牌、上传授权、`rbtoken` 和临时请求头；
- 与功能结果无关的账号 UID、机构 ID 和真实姓名；
- 浏览器配置、缓存和开发期抓包数据。

知识库、上传和签名模块只把临时凭据放在单次内存上下文。服务端错误消息在返回前会移除已知敏感值。

## 平台变化

不同学校、账号角色和采购模块会暴露不同功能。项目同时保存：

- UI 入口是否被观察到；
- 语义动作是否已实现；
- 该动作是否完成真实平台验证。

这三个事实不能互相替代。平台返回维护、无数据、无 URL 或无权限时，运行时报告该状态；不会根据其他账号或旧页面推断当前能力。
